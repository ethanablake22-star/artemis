# Artemis Home & Current Mission Subsystem (V0.0.7)

## Overview

Artemis **Home** serves as the primary operational command center and mission cockpit for Artemis users. Rather than acting as a redundant database layer, Home is an authoritative aggregator and navigator that synthesizes live operational data across existing subsystems:

- **Current Mission**: Focused hero card tracking the active repair, appointment, or document.
- **Today's Schedule**: Chronologically ordered service appointments and timelines intersecting today in the local timezone.
- **Needs Attention**: Critical action items derived strictly from active Work Orders (`awaiting_approval`, `waiting_parts`, `diagnosing`).
- **Active Work**: Prioritized active repairs and diagnostics.
- **Recent Documents**: Authoritatively ordered recent documents from the Library.
- **Quick Access**: Direct creation shortcuts for Work Orders, Appointments, Documents, Customers, and Vehicles.

## 1. Current Mission Data Model

The Current Mission is a lightweight persistent reference pointing to an active Artemis resource:

```typescript
export type CurrentMissionResourceType = 'work-order' | 'schedule-event' | 'document';

export interface CurrentMissionReference {
  resourceType: CurrentMissionResourceType;
  resourceId: string;
  setAt: number; // Authoritative UTC epoch milliseconds generated by Main
}

export interface ArtemisHomeStoreData {
  schemaVersion: 1;
  currentMission: CurrentMissionReference | null;
}
```

### Persistence & Encapsulation
- Stored authoritatively in `app.getPath('userData')/artemis_home_store.json`.
- Main owns resource validation, encapsulation, and atomic disk writes.
- `homeStorage.ts` does not parse underlying storage files directly; it verifies resource existence via owning subsystem storage APIs (`getWorkOrder`, `getScheduleEvent`, `getItem`).

### Initial Eligibility Rules
- **Work Order**: Must be non-deleted and not in `completed` or `cancelled` status.
- **Schedule Event**: Must be non-deleted and not in `completed`, `cancelled`, or `no_show` status.
- **Document**: Must be an existing non-deleted Library item with `type === 'document'`.

### Archival Resilience
If a referenced resource is later archived or its status changes, Home does NOT silently drop the reference. Instead, Home renders an informative archived notice and allows the user to view details or clear the mission manually.

## 2. Aggregation & Failure Isolation

Home operates under strict fault-isolation principles:
1. **Asynchronous Isolation**: Data loading across Automotive, Scheduling, Library, and Home occurs concurrently without tight coupling.
2. **Partial-Failure Tolerance**: If one subsystem encounters a disk or IPC error, its specific section renders a localized error state while the rest of Home remains fully interactive and accessible.
3. **No Fabricated Health Metrics**: Sections reflect real operational data; no mocked status summaries or placeholder counters are rendered.

---

## 3. Universal Tab Navigation

All interactive elements in Home seamlessly invoke existing Universal Tab Shell methods:
- Work Orders -> `openWorkOrderTab(id, workOrderNumber)`
- Appointments -> `openScheduleEventTab(id, title)`
- Documents -> `openDocumentTab(id, name)`
- Calendar Hub -> `openScheduleTab()`
- Automotive Hub -> `openTab({ type: 'automotive' })`
- Library -> `openTab({ type: 'library' })`
