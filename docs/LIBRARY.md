# Artemis Library Architecture & Data Model

## Overview

**Artemis Library** is the authoritative, local-first file and asset subsystem for the Artemis desktop platform. It operates inside the universal tab shell, providing an intuitive, high-performance file-browser interface for organizing projects, specifications, schematics, telemetry logs, and documents.

---

## Authoritative Security & Persistence Boundary

To ensure complete data integrity and adhere to desktop security best practices, **the Electron Main Process is the sole authority for all data validation, UUID generation, atomic file storage, and cascading soft-deletions.**

```
┌─────────────────────────────────────────────────────────────┐
│                      React / Library UI                     │
│         (BreadcrumbNav, FolderTreeView, LibraryTab)         │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│                        LibraryContext                       │
└──────────────────────────────┬──────────────────────────────┘

┌──────────────────────────────▼──────────────────────────────┐
│             LocalLibraryRepository (Renderer)               │
└──────────────────────────────┬──────────────────────────────┘
                               │ Narrow IPC Calls
                               ▼
               artemisAPI.library.list(...)
               artemisAPI.library.get(id)
               artemisAPI.library.create(options)
               artemisAPI.library.update(id, updates)
               artemisAPI.library.move(id, newParentId)
               artemisAPI.library.delete(id)
                               │
┌──────────────────────────────▼──────────────────────────────┐
│                    Electron Main Process                    │
│                 (src/main/libraryStorage.ts)                │
│                                                             │
│   ├── Input validation (non-empty names, valid types)       │
│   ├── Authoritative UUID generation (crypto.randomUUID())   │
│   ├── Cycle prevention on folder move                       │
│   ├── Schema version validation & migration framework (v1)  │
│   ├── Server-side recursive cascading soft-deletion         │
│   └── Atomic temp-file JSON persistence                     │
└─────────────────────────────────────────────────────────────┘
```

### Security Rules
1. **No Generic Store Overwrite**: The renderer has no access to a generic `saveItems(items)` method and cannot overwrite the persistent file directly.
2. **Narrow IPC Endpoints**: The renderer can only trigger validated, granular operations (`list`, `get`, `create`, `update`, `move`, `delete`).
3. **No Silent Fallback in Electron**: When running inside Electron, any IPC communication failure is treated as an explicit error and displayed in the UI. Silent fallback to `localStorage` is strictly forbidden in the desktop environment.

## Data Model & Versioned Store Format

Library data is persisted in `app.getPath('userData')/artemis_library_store.json` using a versioned root object:

```json
{
  "schemaVersion": 1,
  "items": [
    {
      "id": "f-root-projects",
      "name": "Projects",
      "type": "folder",
      "parentId": null,
      "createdAt": 1724500000000,
      "updatedAt": 1724500000000,
      "isDeleted": false,
      "metadata": { "description": "Primary engineering and workspace projects" }
    }
  ]
}
```

### TypeScript Data Structures

```typescript
export type LibraryItemType = 'folder' | 'document' | 'file';

export interface LibraryItem {
  /** Authoritative internal UUID generated by Electron Main */
  id: string;
  /** Display name of the item */
  name: string;
  /** Item type discriminator */
  type: LibraryItemType;
  /** Parent folder UUID (null indicates root level) */
  parentId: string | null;
  /** Creation timestamp in milliseconds (epoch) */
  createdAt: number;
  /** Last modification timestamp in milliseconds (epoch) */
  updatedAt: number;
  /** Soft-delete flag (true = archived / moved to trash) */
  isDeleted: boolean;
  /** Extensible metadata */
  metadata?: {
    size?: number;
    description?: string;
    tags?: string[];
    mimeType?: string;
    [key: string]: unknown;
  };
}

export interface LibraryStoreData {
  schemaVersion: 1;
  items: LibraryItem[];
}
```

## Authoritative Mutation Lifecycle

### 1. Item Creation (`createItem`)
- **Main Process Validation**: Ensures `name` is non-empty and `type` is valid. Verifies `parentId` exists and is a folder.
- **UUID Assignment**: Generates a cryptographic UUID via `crypto.randomUUID()`.
- **Atomic Save**: Persists to disk via temp-file write and atomic rename.

### 2. Item Rename & Update (`updateItem`)
- **Main Process Validation**: Verifies `id` exists; validates non-empty `name`.
- Updates `updatedAt` timestamp and saves atomically.

### 3. Folder Movement & Cycle Prevention (`moveItem`)
- Verifies target parent exists and is a folder.
- **Cycle Prevention**: Recursively inspects ancestor hierarchy to prevent moving a folder into itself or any of its descendants.

### 4. Cascading Soft-Deletion (`deleteItem`)
- `delete(id)` exclusively performs **recursive soft deletion** (`isDeleted = true`).
- The main process traverses all descendant children, subfolders, and documents, marking every descendant `isDeleted: true` and updating their timestamps.
- **No Hard Delete**: Permanent deletion is withheld from the renderer API until a privileged Trash/Purge subsystem is established in a future milestone.

---

## Schema Migration Framework

The main storage manager validates `schemaVersion` upon reading the store:
- `schemaVersion === 1`: Validated and loaded directly.
- `schemaVersion > 1`: Throws `UnsupportedSchemaVersionError` to prevent data corruption from future versions.
- **Migration Pipeline**: Provides a structured migration dispatcher for future schema transformations (`v1 -> v2 -> v3`).

---

## Migration Path to Artemis Core Database

Because the UI interacts strictly through narrow operations via `ILibraryStorageRepository`:
1. The JSON file store can be swapped for SQLite, DuckDB, or Artemis Core Embedded Database without modifying any React components.
2. The schema maps 1-to-1 to relational SQL tables with foreign keys on `parentId`.
